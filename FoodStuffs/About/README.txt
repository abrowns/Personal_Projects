"FoodStuffs" Project

Description --> The "FoodStuffs" project was originally a project for my database concepts
class, and I'd like to show it off as a great example of database knowledge, python knowledge,
and solid design capabilities. The main purpose of this project was to design a database to fulfill
some sort of purpose. The "FoodStuffs" database is meant to be a better way to track health, and more
information about that aspect of the project can be found in "Initial Study Analysis". Because this
project orginally revolved around the design concept, all the diagrams were made first, followed by 
the actual database, and ended with a small python application that only ran a single function.
After the class ended, I took the liberty of progressing the development of the application, and added
a bit more functionality, but haven't finished everything I would like to implement, and all of the
features currently implemented aren't fully complete.

Database --> Before the python file can be ran, the database needs to be setup, along with
the sql procedures.

Main File --> The main file to run is "Application.py", and you will be met with a
login to the database/application.

Setup --> To "login", you must enter your mysql password so that you don't have to manually change it
in the code for all the procedures to work properly. When it asks for a username, the built in 
usernames are "C_1", "C_2", "C_3", ..., "C_10", for the purpose of later making an account saving 
feature.

Features --> The only working features in the application are the 1st and 2nd options when the 
application first runs. The first feature called "All Meals" will display the user's saved meals,
which itself isn't a completed feature yet, but the displaying is there. The second feature is a 
search feature which allows the user to search any food item and/or ingredient; and this part works 
exactly how you would think a search feature works where you can search anything, and the results are
displayed on the screen.
